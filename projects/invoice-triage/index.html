Invoice triage workflow

Every new supplier invoice is read, checked, logged and sent to the right inbox: "ready to approve" or "needs a person", with the reasons. The workflow removes the reading and checking. It never changes a price.

Workflow file → The system behind it

The flow

Seven nodes and one decision.

New invoice in the inbox foldern8n watches the folder
Read-only summarypython -m invoicepricing summary <file> returns JSON (proved or not, problems, decisions needed), and a code node parses it
Log to Google Sheetsone row per invoice: a running log of everything that came in
Proved, and nothing to decide?the only branch in the workflow
Yes → "Ready to approve"email with the totals; one tap in the app
No → "Needs a person"email listing each reason, product by product

Why it stops there

Prices are a business decision.

Automating the write would have been easy. I left it out on purpose: the workflow only calls a read-only command, and the one way to change the database stays the app's write path, with simulation, a verified backup and an undo log. If the workflow ever misbehaves, the worst outcome is a wrong email.
